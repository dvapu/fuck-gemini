# PATCH 2026-11-24 - what the MCP calls actually cost us, and what changed

Written after a day of driving this pool from an orchestrator to do real work (a C++ game-mod
bug hunt). Every item below is a friction point that actually happened, not a hypothetical.

## 1. The failures we hit, in the order they bit

| # | Symptom seen by the caller | Root cause | Cost |
|---|---|---|---|
| 1 | status TRUNCATED with changes [] | reply cut at max_tokens=16384; the tool returned the error and dropped the partial edits | whole work orders lost, 3 times |
| 2 | "goal Field required" / "files Field required" | code_task declared files as required and the caller named the argument work_order | 1 wasted call |
| 3 | status UNPARSABLE with no edits | model answered with prose, a markdown fence, or a bare JSON array of changes | 4 work orders lost |
| 4 | cannot tell whether a patch is live | the client keeps the server process; editing the .py changes nothing until a restart, and nothing reported which code was running | 1 wrong conclusion |
| 5 | tools vanish after killing the stale process | the client does not reconnect a stdio server it lost | gemini tools gone for the session |

## 2. What changed (agy_pool.py 2.1.0 -> 2.2.0)

1. Continuation instead of death: code_task uses _chat_continue, so a cap-hit reply is
   continued (up to 2 extra turns) and joined.
2. Salvage: _salvage_changes() keeps every change object that is complete, so a cut-off
   answer is PARTIAL with real edits instead of empty. The note says what happened.
3. Budget: default max_tokens 16384 -> 32768 for code_task, 16384 -> 32768 per agent in fanout.
4. Argument tolerance: work_order is an alias of goal; goal and files are optional with a
   readable error; files entries may be a bare path string or a {path} object without content,
   read from disk like paths.
5. One cold retry: when a reply is not a JSON object the tool re-asks once at temperature 0.1
   with an explicit "first character {, last }" reminder, then salvages. A bare array of
   changes is wrapped instead of rejected.
6. Prompt discipline: no markdown, one sentence of analysis, prefer patch over rewriting a
   long file - the two things that push a reply past the cap.
7. Self-reporting: status returns server_version and code = {file, sha256_12, file_mtime,
   process_started, restart_needed}, so "is my patch live?" is one call. restart_needed is
   true when the file on disk is newer than the process.
8. review got the same alias/tolerance treatment as code_task.

## 3. Tests

tests/test_truncation.py and tests/test_ergonomics.py pin all of the above with stubbed model
calls (no network): truncation -> PARTIAL, prose -> retry -> OK, prose twice -> UNPARSABLE with
raw tail, bare array -> wrapped, aliases, disk paths, status stamp. The v2, v3 and pacing suites
still pass.

## 4. Operational notes

- A patch is only live after the client restarts the server. Check code.restart_needed first.
- Killing the server process removes the MCP tools from a running session. Fall back to
  poolbatch.py (same pool, own process, no MCP):
  python poolbatch.py tasks.json --outdir out --max-tokens 9000
- Give the pool one small unit per call (one file, one function). A 250-line function came back
  complete on the first try; a 700-line file did not come back at all.
